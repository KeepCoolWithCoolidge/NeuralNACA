    Reproducing the results¶

    Every number in this documentation is produced by code in this repository from files in this repository, and can be re-derived at three levels of depth. Each level re-checks the central claim: lower MAE than NeuralFoil-xxxlarge for \(C_L\), \(\ln C_D\) and \(C_M\), with the 95 % interval excluding parity.

    git clone https://github.com/KeepCoolWithCoolidge/NeuralNACA.git && cd NeuralNACA
python -m pip install -e ".[neuralfoil,plot,test]"
neuralnaca reproduce --level 0          # seconds-minutes, no XFOIL
neuralnaca reproduce --level 1          # retrain all replications, no XFOIL
neuralnaca reproduce --level 2          # regenerate the XFOIL data too (needs XFOIL)

    The command exits with status 0 if everything reproduces and 1 otherwise; --json report.json saves the details and --seeds 0,3 restricts it to some replications. Levels 1 and 2 write into reproduction/ and never overwrite the shipped results.

    Level 0: verify¶

    Inputs: shipped weights (benchmarks/models/) and shipped XFOIL test sets (data/xfoil/). Checks: every file matches the SHA-256 recorded in its result file. Predictions are recomputed, NeuralFoil is re-run, the metrics are compared with the shipped results (relative tolerance 10⁻⁴) and the claim is re-tested.

    This isolates the evaluation: if level 0 passes, the published comparison follows from the published models and data. It also catches a different NeuralFoil version (reported, since its predictions may change between releases).

    Level 1: retrain¶

    Inputs: the shipped XFOIL training sets. Does: trains every replication's model from scratch with the published recipe, then evaluates as in level 0.

    • Same platform and software versions: training is deterministic, so the retrained weights are bit-identical to the shipped ones and the metrics agree exactly. The development machine re-derived replications 0-2 bit for bit from the original research script. Training gave identical weights with 1 and 2 PyTorch threads, and the test suite checks determinism.
    • Different platform: floating-point summation order may differ (CPU, BLAS, PyTorch version), and training amplifies tiny differences. The metrics then differ by an amount bounded by the training-seed study: retraining the same data with different seeds is a worst case for "same recipe, different floating-point path". The tolerance is four standard deviations of that study's MAE (at least 3 %; 8.8 % with the shipped study, set by \(C_M\)), and the claim must still hold.

    Level 2: regenerate¶

    Requires: XFOIL (see Installation). Does: re-runs XFOIL on the same designs (same Sobol and random seeds, so the same conditions), compares your labels with the shipped ones (convergence counts, agreement on commonly converged points), then retrains and evaluates.

    With the documented XFOIL builds the labels agree exactly: a fresh build made with scripts/install_xfoil_python.sh reproduced the shipped results bit for bit, and scripts/build_xfoil_binary.sh rebuilt a byte-identical executable. With other XFOIL builds, differences concentrate near stall. Level 2 then uses a wider tolerance and the claim check as its pass criterion.

    What is shipped, and how it is protected¶

    path content
    data/xfoil/ every XFOIL data set (inputs, outputs incl. non-converged runs, provenance)
    benchmarks/models/ every trained model of every experiment
    benchmarks/results/ every result (JSON) and the per-point predictions of the main runs
    benchmarks/MANIFEST.json SHA-256 of all of the above, plus the package weights and test fixtures
    docs/results/tables.md generated by neuralnaca report from benchmarks/results/
    docs/assets/*.png generated by neuralnaca figures

    The test suite (pytest -m benchmark) checks all of the following, so an inconsistency cannot go unnoticed:

    • every file matches the manifest;
    • every data set reproduces its declared design (to the last bit, except the Reynolds number, which is allowed a relative 10⁻¹² because 10**x is not bit-identical across operating systems);
    • no test airfoil appears in its replication's training set;
    • every result file matches its model and data hashes;
    • the claim holds in every replication and pooled;
    • the package's weights are the replication-0 model;
    • docs/results/tables.md is exactly what neuralnaca report produces;
    • the headline numbers in the README are the computed ones;
    • every ratio-with-interval quoted in any documentation page appears in the generated tables.

    Re-running the experiments from scratch¶

    neuralnaca bench main --seeds 0-4          # needs XFOIL unless data/xfoil/ is present
neuralnaca bench protocol --seeds 0        # needs XFOIL (and aerosandbox) for the alternative ground truths
neuralnaca bench variance --seeds 0
neuralnaca bench ablation --seeds 0-2 --variants plain,no_panel,no_symmetry,no_drag_prior,full
neuralnaca bench curve --seeds 0-2 --sizes 512,1024,2048,4096
neuralnaca bench support --seeds 0-4
neuralnaca bench ablation --seeds 0 --residuals --variants full
neuralnaca bench curve --seeds 0 --sizes 8192     # needs XFOIL for the extra 4,096 runs
neuralnaca bench speed
neuralnaca report && neuralnaca figures && python scripts/make_manifest.py

    With existing files in place, each step reuses data and models whose recorded configuration matches, and recomputes anything that does not. Add --retrain to force training.

    Reference environment¶

    The published results were produced on Linux x86-64 with 2 CPU cores. The software versions are listed at the end of the generated tables and recorded in every result file. XFOIL solved about 12 cold-start runs per second on 2 cores (a replication's 7,096 runs in about 10 minutes); training one 5-member model took 5-7 minutes.
