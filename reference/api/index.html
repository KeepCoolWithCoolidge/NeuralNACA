    Python API¶

    The package is organised in layers; most users only need the first.

    module purpose
    neuralnaca get_aero, NeuralNACA, parse_naca, naca4_coordinates, DEFAULT_DOMAIN, warnings
    neuralnaca.domain the validated domain and the sampling designs
    neuralnaca.geometry NACA 4-digit geometry (NumPy and differentiable PyTorch)
    neuralnaca.panel the differentiable Hess-Smith panel method
    neuralnaca.model features, network, symmetry check, weights files
    neuralnaca.training the training recipe
    neuralnaca.support training-support estimate
    neuralnaca.xfoil XFOIL configuration and batch driver
    neuralnaca.data XFOIL data sets, generation, integrity
    neuralnaca.evaluation metrics and paired statistics
    neuralnaca.baselines NeuralFoil wrapper
    neuralnaca.benchmark the experiments behind every published number
    neuralnaca.report, neuralnaca.plotting generated tables and figures

    Predictions¶

    neuralnaca.api.NeuralNACA ¶

    A trained surrogate for NACA 4-digit polars (CL, CD, CM; n_crit = 9, Mach 0, free transition).

    Use :meth:pretrained for the shipped model or :meth:load for your own weights file.

    Examples:

    >>> from neuralnaca import NeuralNACA
>>> model = NeuralNACA.pretrained()
>>> aero = model.predict("2412", alpha=[0.0, 4.0], Re=1e6)
>>> sorted(aero)
['CD', 'CD_std', 'CL', 'CL_std', 'CM', 'CM_std', 'in_domain', 'lnCD_std', 'supported', 'xfoil_convergence']

    load(path, domain=DEFAULT_DOMAIN, support='auto') classmethod ¶

    Load a weights file written by :func:neuralnaca.model.save_model.

    support="auto" also loads <name>.support.npz next to the weights if it exists (see :mod:neuralnaca.support); pass a path to use another file or None to skip.

    pretrained() classmethod ¶

    The shipped model (see :data:DEFAULT_WEIGHTS).

    fingerprint() ¶

    SHA-256 (first 16 hex digits) of the network parameters - identifies a model unambiguously.

    Type Description

    CL, CD, CM (ensemble mean; CD = exp(mean ln CD)), their ensemble standard deviations CL_std, lnCD_std (relative drag spread), CD_std (= CD * lnCD_std), CM_std, in_domain (inside the validated box), xfoil_convergence (estimated probability that XFOIL converges at this condition, from the training data) and supported (in the domain, convergence probability >= 0.5 and drag inside the training range). Predictions that are not supported are extrapolations into a region where XFOIL itself rarely converges (mostly deep stall of thin sections at low Reynolds number); they can be physically meaningless and are flagged with an :class:~neuralnaca.domain.UnsupportedWarning.

    Geometry¶

    neuralnaca.geometry ¶

    NACA 4-digit section geometry.

    The thickness distribution is the classical open-trailing-edge one (coefficient -0.1015), which is what XFOIL's NACA command and AeroSandbox's Airfoil("naca2412") generate. Thickness is applied perpendicular to the mean camber line.

    naca4_coordinates(m, p, t, n_per_side=100) ¶

    Coordinates in Selig order (upper trailing edge -> leading edge -> lower trailing edge).

    Cosine spacing with n_per_side points per surface (the leading-edge point is shared), i.e. 2 * n_per_side - 1 points in total. These are the coordinates handed to XFOIL (which re-panels them) and to NeuralFoil.

    Panel method¶

    neuralnaca.panel ¶

    Differentiable Hess-Smith panel method (the "physics" backbone of the surrogate).

    Inviscid, incompressible potential flow around the section is represented by a constant-strength source on every panel plus one vortex strength shared by all panels; the flow-tangency condition at the panel midpoints and the Kutta condition (equal tangential velocity magnitude on the two trailing-edge panels) close the linear system.

    Because potential flow is linear in the free-stream vector, two unit solutions (free stream along x and along y) are enough to express the inviscid lift and moment analytically for any angle of attack:

    .. math::

    C_{L,\mathrm{inv}}(\alpha) = A_L\cos\alpha + B_L\sin\alpha, \qquad
C_{M,\mathrm{inv}}(\alpha) = A_M - (B_M\cos^2\alpha + C_M\cos\alpha\sin\alpha + D_M\sin^2\alpha)

    with :math:C_L from the Kutta-Joukowski theorem (:math:C_L = 2\Gamma/(V_\infty c)) and :math:C_M about the quarter chord from integration of :math:C_p = 1 - V_t^2/V_\infty^2. The six constants depend only on geometry and are computed once per airfoil by :func:airfoil_constants; :func:inviscid then evaluates them (differentiably in alpha) inside the network.

    Model¶

    neuralnaca.model ¶

    Network architecture, input features and the weights file format.

    The model predicts y = [CL, ln CD, CM] as a physics base plus a learned correction:

    .. math::

    y = y_\mathrm{base}(\text{panel method, flat-plate drag}) + \Delta y_\theta(\text{features})

    and the correction is made exactly mirror-symmetric: reflecting a section about its chord line (:math:m\to-m, :math:\alpha\to-\alpha) must give :math:C_L\to-C_L, :math:C_M\to-C_M and the same :math:C_D. With :math:x the features and :math:\bar x the features of the reflected case,

    .. math::

    \Delta C_L = \tfrac12[f_L(x) - f_L(\bar x)],\quad
\Delta \ln C_D = \tfrac12[f_D(x) + f_D(\bar x)],\quad
\Delta C_M = \tfrac12[f_M(x) - f_M(\bar x)].

    This only holds if every feature transforms correctly under the reflection, which is why the camber-position gate is an even function of m (see :data:FEATURES_VERSION).

    Ablation variants (used in the benchmark to measure what each piece of physics contributes) remove one ingredient at a time; "full" is the shipped model.

    Training¶

    neuralnaca.training ¶

    Training of the ensemble surrogate.

    Recipe (all members trained simultaneously with batched matrix products, each on its own minibatch stream):

    • loss: smooth-L1 (Huber, beta = 0.1) on [CL, ln CD, CM] scaled by LOSS_W - robust to the occasional erratic XFOIL point near stall;
    • Adam with a one-cycle learning-rate schedule (peak 3e-3);
    • exponential moving average (EMA) of the weights over the second half of training - the EMA weights are the model;
    • optional autograd "PINN" residuals on unlabelled collocation points (off by default; in our experiments they do not improve accuracy, see the documentation).

    TrainConfig dataclass ¶

    Hyper-parameters. The defaults are the ones used for every reported result.

    physics_residuals(net, col) ¶

    Autograd residuals on unlabelled collocation points (all tensors shaped (K, nc)).

    • slope: pre-stall dCL/dalpha within [0.5, 1.3] x the inviscid slope (XFOIL: 97 % of intervals);
    • curv: |d2CL/dalpha2| <= 0.15 per deg^2 in the pre-stall range (XFOIL: 99 %);
    • re: d ln(CD) / d ln(Re) <= 0.1 - profile drag falls with Reynolds number (XFOIL: 98.7 %).

    Training support¶

    neuralnaca.support ¶

    Where is a prediction backed by training data?

    XFOIL does not converge everywhere in the domain (deep stall of thin sections at low Reynolds number is the main region). The surrogate never saw data there, so its predictions are unconstrained extrapolations - drag in particular can grow without bound. The benchmark cannot score these points (XFOIL has no answer either), so they must be flagged instead.

    :class:SupportModel estimates the probability that XFOIL converges at a condition from the training set itself (a distance-weighted k-nearest-neighbour vote over converged / non-converged training runs; no extra XFOIL runs), and also checks that the predicted drag stays inside the range of the training targets. A prediction is supported if it is inside the domain, the estimated convergence probability is at least threshold and CD does not exceed cd_max. The documentation reports how well this flag separates converged from non-converged held-out points.

    XFOIL¶

    neuralnaca.xfoil ¶

    Running XFOIL: the "teacher" that generates training data and the ground truth for evaluation.

    Two interchangeable backends are supported:

    "module" The xfoil Python extension (https://github.com/daniel-de-vries/xfoil-python), in-process. About four times faster than the executable. One persistent instance per worker process (every new XFoil() object leaks a copy of the Fortran library), recycled every 400 points. "binary" An XFOIL 6.99 executable, one process per point (crash- and hang-proof). The polar save file is parsed.

    Two solution protocols:

    "cold" (default, used for all training and test data) Every point is solved independently from a fresh boundary-layer initialisation. The answer for a point does not depend on which other points were run. "nf-sweep" Replicates the protocol of NeuralFoil's training data (asb.XFoil.alpha with start_at=0): points are reached by an angle-of-attack sweep in sweep_step increments that starts next to 0 deg on the same side of zero and is warm-started from the previous converged point; max_iter is 200. Used only in the ground-truth sensitivity study.

    and two geometry representations:

    "naca" The exact NACA 4-digit coordinates (:func:neuralnaca.geometry.naca4_coordinates). "kulfan" The 8+8-weight Kulfan (CST) fit that NeuralFoil makes of those coordinates internally, including NeuralFoil's normalisation (rotation / scaling) and its moment-reference correction - i.e. the geometry NeuralFoil actually analyses. Needs aerosandbox. Used only in the ground-truth sensitivity study. "naca-normalized" Control case: the exact NACA coordinates passed through the same normalisation and frame transformation as "kulfan" but without the Kulfan fit. Separates the effect of the shape fit from that of the frame handling.

    Workers that die inside XFOIL (segmentation faults, floating-point traps) are contained by :func:run_xfoil: failed chunks are split and retried, and a point that kills an isolated worker is reported as not converged.

    Evaluation¶

    neuralnaca.evaluation ¶

    Error metrics, paired-bootstrap comparisons and regime breakdowns.

    All metrics follow NeuralFoil's paper: absolute errors of CL, ln(CD) and CM (ln CD errors are roughly relative drag errors: 0.01 in ln CD ~ 1 % in CD). Every comparison is paired - both models are scored on exactly the same XFOIL-converged points - and uncertainties come from a paired bootstrap over test points.

    Benchmark¶

    neuralnaca.benchmark ¶

    The benchmark: every reported number is produced by the functions in this module.

    Layout of a benchmark root (the repository root by default)::

    data/xfoil/                 XFOIL data sets (train_<n>_s<seed>_<tag>.npz, test_<n>_s<seed>_<tag>.npz)
benchmarks/models/          trained weights (<variant>_k<K>_n<n>_s<seed>[_ts<train seed>].npz)
benchmarks/results/         JSON results (+ per-point predictions as .npz)
benchmarks/MANIFEST.json    SHA-256 of every shipped data / model / result file
    Experiments

    main one replication: fresh Sobol training set + i.i.d. test set (seed), train, evaluate vs NeuralFoil variance retrain on the same data with different training seeds (spread due to optimisation alone) ablation remove one physics ingredient at a time (same data, same recipe) curve error vs number of XFOIL training runs (Sobol prefixes) protocol sensitivity of the comparison to the definition of the XFOIL ground truth reproduce re-run / re-check the shipped results at three levels of depth

    run_protocol_study(seed=0, layout=Layout(), spec=BenchmarkSpec(), workers=None) ¶

    How much does the conclusion depend on how the XFOIL ground truth is defined?

    The test points of replication seed are re-solved with XFOIL under four definitions (cold start vs. NeuralFoil's warm-started sweep protocol; exact NACA geometry vs. the Kulfan fit NeuralFoil analyses). The shipped model (trained on cold/naca data) and NeuralFoil are scored against each, on the points that converged under all definitions. XFOIL-vs-XFOIL differences between definitions are reported as well: they bound how precisely any surrogate can be said to "match XFOIL".

    reproduce(level=0, seeds=None, layout=Layout(), out=None, workers=None, rel_tol=None) ¶

    Re-derive the shipped results and compare.

    Levels

    0 Verify: shipped weights + shipped test data -> metrics (seconds). Must agree with the shipped results to floating-point precision (rel_tol default 1e-4). 1 Retrain: shipped training data -> new weights -> metrics (~7 min per seed on 2 CPU cores). Identical on the reference platform; elsewhere the model metrics must fall inside the band set by the training-seed variance study (rel_tol default: 4 standard deviations of the MAE, at least 3 %). 2 Regenerate: your XFOIL -> new data sets -> retrain -> metrics (~20 min per seed). Data agreement with the shipped sets is reported; the claim check (CI upper bound of the MAE ratio < 1 for all three outputs) is the pass criterion.

    In every level the central claim is re-checked: NeuralNACA's MAE is lower than NeuralFoil-xxxlarge's for CL, ln CD and CM with the 95 % paired-bootstrap interval excluding 1.

    summarize_mains(results_dir=Layout().results) ¶

    Pool the per-point errors of all main replications: aggregate MAE ratios with bootstrap CIs.

    run_support_study(seeds, layout=Layout(), n_airfoils=2000, n_conditions=25) ¶

    How well does the support flag (:mod:neuralnaca.support) identify where XFOIL fails, and what is lost?

    Per replication: the support model is built from the training set only and evaluated on the held-out test set - AUC for predicting XFOIL non-convergence, the share of converged / non-converged test points flagged, and the MAE of both models on the supported converged points. The share of the domain volume that is unsupported is estimated by Monte Carlo (n_airfoils random sections x n_conditions random (Re, alpha) each).
